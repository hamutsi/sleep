# מאמן שינה 🦉

אפליקציית PWA פרטית שמלווה חבר של ליאור (גבר 47, סטטין, טרום סוכרת, Fitbit Air) בשיפור השינה. מבט אחורה על אתמול, מבט קדימה על מה שווה לנסות, "למה ככה?" ליד כל תובנה, וצ'אט Gemini.

**כתובת:** https://sleep.adaptation.work · **סטטוס:** פרוס: התחברות, חיבור ל-Google Health (עם איחוד קטעי שינה ללילה אחד כמו באפליקציה של גוגל), הלילה האחרון, יומן אוכל בצילום (Gemini), רישום מהיר של קפה ואלכוהול, יומן אימונים, בדיקת בוקר, פרופיל, לשונית "מאמן" (שיחה יומית עם Gemini), **תובנות יומיות** (מבט אחורה, בנתונים שלך, מחקר היום, צעד קטן, סיכום שבוע ביום שישי), כפתור **"למה ככה?"** וספריית מחקרים לעיון חופשי. בבנייה: בדיקות דם, רדאר לונג'יביטי שבועי. התוכנית המלאה: [PLAN_v1.md](PLAN_v1.md).

## שתי פריסות מאותו קוד

| יעד | כתובת | Worker | מסד |
|---|---|---|---|
| `friend` | https://sleep.adaptation.work | `sleep-coach` | `sleep-coach` |
| `lior` | https://lior.sleep.adaptation.work | `sleep-coach-lior` | `sleep-coach-lior` |

הקוד משותף, ולכן כל שיפור מגיע לשניהם. הנתונים, הסיסמה, החיבור לגוגל והסודות נפרדים לגמרי.
מה ששונה בין המשתמשים (גיל, אימונים, סטטין, טרום סוכרת) מוגדר ב-`src/persona.js` ונבחר לפי `PERSONA` ב-`wrangler.toml`.
בחיבור לגוגל: אותו Client משמש את שתיהן, אבל כל כתובת צריכה Redirect URI משלה ב-Google Cloud (`<כתובת>/api/gh/callback`), וכל חשבון Gmail צריך להיות ב-Test users.

## פריסה

```bash
bash deploy.sh          # שתי הפריסות
bash deploy.sh lior     # רק אחת
bash set-secrets.sh lior   # סודות, פעם ראשונה לכל יעד
```

יוצר מסד D1 (בפעם הראשונה), מריץ מיגרציות, פורס ומחבר את הדומיין. בטוח להריץ שוב. יוצר אקראית את `SESSION_SECRET` ואת `DATA_KEY` ולא מחליף אותם אם כבר קיימים.

**אזהרה:** לעולם לא להחליף את `DATA_KEY` אחרי שנשמרו נתונים, כי אי אפשר יהיה לפענח את הטוקנים המוצפנים.

## סודות

```bash
bash set-secrets.sh
```

| סוד | מה זה |
|-----|-------|
| `LOGIN_PEPPER`, `PASS_VERIFIER` | נגזרים מסיסמת הכניסה של החבר. הסיסמה עצמה לא נשמרת בשום מקום |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | מ-Google Cloud, ראה [setup/google-cloud-setup_v1.md](setup/google-cloud-setup_v1.md) |
| `GEMINI_API_KEY` | המפתח של החבר. נבדק לפני השמירה. חייב להיות מפרויקט מקושר לחיבור (אחרת גוגל עשויה להשתמש בתוכן) |
| `SESSION_SECRET`, `DATA_KEY` | נוצרים אקראית ב-deploy.sh |

כלל: סודות לא מודבקים בצ'אט ולא נשמרים בקבצים.

## ספריית "למה ההסבר" (למה ככה?)

- כל תובנה מקבלת כפתור שפותח הסבר בעברית פשוטה, חוזק ראיות, "מה זה לא אומר", מקורות וסרטונים. **המודל לא כותב קישורים**: הוא מצטט מזהי נושאים בלבד, והאפליקציה מציגה את המקורות מהספרייה.
- הספרייה נבנית מ-`evidence/part_*.json` בפקודה `node tools/build_evidence.mjs`, שנכשלת אם חסר שדה, אם כתובת מחוץ לרשימה המותרת או אם יש מקף ארוך. `deploy.sh` מריץ אותה לפני כל פריסה.
- אימות: `python3 ../../../T-tools/check_links.py evidence/part_L1_v1.json evidence/part_L2_v1.json --workers 3` (PubMed, Crossref, YouTube), ו-`python3 tools/verify_numbers.py evidence/*.json --fetch` (כל מספר בטקסט העברי חייב להופיע במקור). 429 מ-PubMed הוא הגבלת קצב, לא קישור שבור: מריצים שוב.
- נושאי תרופות ותוספים (תופעות לוואי של סטטין, אינטראקציות, מלטונין, מגנזיום) נגישים רק מ"ספריית המחקרים" או משאלה למאמן, ולא מוצגים כ"מחקר היום" (R-MED-3).

## לקחים מהחיבור הראשון לגוגל

- `invalid_client` בהחלפת הקוד: כמעט תמיד סוד שגוי. באפליקציה, מתחת לכפתור החיבור, יש **"בדיקת הגדרות החיבור"** שמראה אם גוגל מכירה את ה-Client ID והסוד, ואת אורך הסוד ששמור (סוד תקין: כ-35 תווים, מתחיל ב-GOCSPX-). גוגל מציגה סוד במלואו רק ברגע היצירה (Add secret).
- ב"מאמן", אם גוגל דוחה את מפתח Gemini ("API key not valid"), יש שם **"בדיקת מפתח Gemini"**. מפתח תקין מתחיל ב-AIza (39 תווים) או בפורמט החדש AQ.
- סודות מוזנים בטרמינל בלבד (`wrangler secret put NAME`), ומנוקים בשרת מתווים נסתרים.
- Google Health מחזירה לפעמים כמה קטעי שינה ללילה אחד (השני מסומן "nap"). האפליקציה מאחדת קטעים שהפער ביניהם עד 3 שעות, כך שהסיכום זהה לאפליקציה של גוגל.

## עקרונות

- **הנתונים רק ב-D1**, דרך API מוגן. הקבצים הסטטיים ציבוריים ואינם מכילים מידע אישי.
- **אין ייעוץ רפואי.** אף פלט לא מייעץ לשנות תרופה ואין אבחנות (כללי הבטיחות ב-PLAN_v1.md).
- **מפתח Gemini רק בשרת.**
- **RTL:** כל ערך שמשלב מספר ויחידה באנגלית (mg/dL, HRV) עטוף ב-`.ltr`, אחרת הסדר מתהפך.
- **עדכונים:** קבצי האפליקציה מוגשים עם `Cache-Control: no-cache`, ה-service worker מבקש מהרשת קודם, ולכן עדכון מגיע לחבר בפתיחה הבאה.
